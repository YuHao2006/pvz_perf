# 高清网页包约束

2026-11-17 用户确认：B站大包体上限按 140 MB 规划。

- 高清网页包只构建原生 Memory64 / wasm64，不附带 wasm32。
- 优先 WebGPU，考虑提供 wasm64 + WebGL 2 后端作为兜底。
- 两个后端共用同一份资源 data、设置和存档，不重复放高清 PAK。
- 不支持 Memory64 的浏览器明确提示兼容性，不下载其他位数的程序。
- 用户于2026-11-17明确要求不透明图片使用JPG：后续默认开发／测试资源采用PNG＋JPEG混合编码；此前注明“无损”的测试包仍保留，不能把新包继续称为全无损。JPEG为质量95、4:4:4，母图保留无损PNG。
- B站发布资源的压缩方案单独评估；140 MB 是完整包预算，需要计入两个运行时及网页文件。

现有 CMake 支持 PVZ_WEB_MEMORY64，package_toy.py 支持 memory64 与 webgl-build 组合，并验证两套运行时共用的数据包一致。当前这一组合的高清网页构建尚未验证，不能据此声称成品已经可发布。

转换JPEG前的修复版 2×桌面无损包：main.pak64 165,390,555 字节，完整 ZIP 168,512,011 字节，含生成的完美存档。416 张 PNG 解码后 RGBA 与 2×源图逐像素一致。它超过 140 MB，不能直接作为本轮 B站包。
