# Reanim / Particle v7：浮点源数据与整数时间驱动的运动方案

状态：正在实施和验证；源定义/编译器、运行时整数时间、根运动、主步长粒子和 v3.3 存档已接入。

## 目标与一致性边界

- DSL 中的参数使用普通小数，生成 C++ 的 `float` 数据，不限制三位精度。
- 同一动作、初始进度、速度及同一整数时间轴上的状态切换，在相同累计时间处得到相同的 reanim 进度与根运动位置，不受外层更新拆分影响。
- 从整数时间或相位直接求值的参数可以使用浮点；不会把采样结果回写为下一步计算的起点。
- 仅改变数值表示不能让碰撞、力场或逐更新随机采样自动与步长无关；粒子、追踪弹与巨型坚果碰撞按主逻辑步进处理，允许不同步长产生行为差异。
- v7 是 reanim / particle 定义与编译器版本，不等于游戏版本或存档版本。存档变化单独升级，不覆盖原格式。

|---|---:|---:|
| X/Y | 231154 | 1 |

23 条 `_ground` 的 1159 个 X、54 个 Y 都能由一位小数还原。

此项为源文本统计，不代表编译器补全的节点时间或运行时随机值也恰好只有三位小数。

## DSL 与静态定义

1. 小数字段采用普通十进制文本，例如 `x: -9.8; scale-x: 0.792;`。
2. 接受正常小数，包括超过三位的小数，检查语法、有限值和 float 范围，并保留文件、行、字段和原文诊断。
3. 数值直接解析为 float；不乘 1000、不预先量化源参数。
4. 帧号、枚举、图片下标、数量等整数语义字段仍保存整数，不把它们乘 1000。
5. 旧 `-10000` 继承占位符在编译期解析并展开。
6. 现有短十进制源文本可以保留；长尾和超过三位的合法值也可以直接编译。
7. 源变换定义生成 float 静态数据；图片帧号等整数语义字段仍为整数。GPU 指针、图集矩形、变体和所有权方案保持现有设计。
8. 粒子曲线节点上下界保存 float；节点时间保留约分的整数分子/分母，不量化到千分网格。省略时间如 `1/3` 仍保留准确比例。

不增加通用小数包装类、访问器或指向另一层包装的指针。使用 public 原始数值成员、静态数组和 const 引用。

## Reanim 的权威播放进度

源 fps 以 `float mFPS` 表示，单位是动画帧/秒。
运行时动画速率保留 `float mAnimRate`（动画帧/秒），不再将随机速度、冰减速或其他运行时结果量化为 milli fps。
主循环按值发布当前绝对纳秒时间 `nowNs`。关卡动画使用
`Board::mMainCounter.mNanoseconds`；视觉动画使用共享的视觉时钟。

动作或速率改变时，先选定一次整数纳秒周期：

```
periodNs = floor(double(frameCount) * 1_000_000_000 / abs(double(mAnimRate)))
elapsedNs = nowNs - startTimeNs
采样：phaseNs, cycles = EuclideanDivRem(originNs + sign(mAnimRate) * elapsedNs, periodNs)
原始源相位 = phaseNs / periodNs
```

周期定义允许一次舍弃不足一纳秒的时长，因此实际周期与无限精度的 fps 比例有小于一纳秒的差别。
这个固定周期用于所有后续采样；没有逐更新的速度积分或时长舍弃。
外层任意整数纳秒拆分在同一绝对时间上得到同样结果。
相位没有每步累加 `rate*dt`。浮点数只在实际变速时确定一次固定周期，后续每次相位推进完全由整数时间计算。

实例保存时钟域、当前恒速段的 `mStartTimeNs`、`mPhaseOriginNs`、`mPeriodNs`、`mOriginCycleCount` 和 `mAnimRate`，以及上次处理的时间戳。生产路径不再逐实例累加年龄。
`SamplePlayback` 从这些字段计算当前相位及带方向的周期数，不重复持久化当前相位缓存。
事件检测保存上次精确整数纳秒采样位置 `mLastFrameNs` / `mLastCycleCount`，`mHasLastFrame` 标记其有效性。
变速时上次位置也映射到新周期，以保留同一原始相位区间。绘制/诊断可临时生成每源帧 `10^9` 单位的原速相位 `clock`，区间为 `[0, 动作帧数 × 10^9)`，它不作为逐步累加的播放状态。
既有 `mLoopCount` 保留“遍历周期次数”的非负语义；倒放也递增，逻辑运动使用独立的带符号采样周期数。

倒放采用明确的欧几里得商余规则，保证周期内 clock 非负。
整局暂停时共享时钟停止，无需修改实例基准。单个动画暂停则将 `mAnimRate` 设为零，保留原周期和相位；它所属时钟仍可继续推进。
非重置变速由 `ApplyRate` 完成：先在旧周期采样原始相位，再将同一比例映射到新周期的整数纳秒位置，最后建立新的时间段。
这一步最多丢弃不足一纳秒，只发生在实际速率改变时；正反向切换也不回到动作开始。
动作切换和主动跳转显式建立新的进度及运动基准，不从取整后坐标反推。
循环模式由 `ChangeLoopType` 切换：保留当前周期内整数相位，建立新的周期计数及事件区间基准，并更新运动绑定代次。
同一模式的重复调用不修改状态；从结束保持切回循环时保留结束位置，首次非零推进才回卷。

乘法、周期长度和插值乘除编译期/运行期都有边界检查；`ReanimClock::MulDiv` 对正常值使用原生整数路径，对宽乘积使用明确的 128 位乘除算法，不能依赖有符号溢出。

速率在同一整数时间发生改变时，跨越该时刻的大步必须分段消费，不能把新旧任一速率套到整步。

## 帧定位与根运动

编译器为每个动作生成动作范围、循环模式需要的采样区间信息、根运动累计位移和速度换算常量。
区分普通模式的 N-1 插值区间与 full-last-frame 模式的 N 区间及末帧保持；禁止统一后偷偷改变原循环语义。

直接由 `phaseNs/periodNs` 计算当前帧及帧内分数，避免先舍入源相位再定位关键帧。源关键帧为 float，根运动使用 double 中间值计算固定周期基准与当前插值，返回正常像素单位的浮点位移。Plant / Zombie 只有一份 float 坐标，不再保存千分定点位置。

```
运动位置 = 固定运动基准
         + 完整周期位移
         + 当前周期累计位移
         - 建立基准时的周期内位移
```

`RootMotion(track, scale, offsetNs)` 计算累计运动函数 `F(t)`，可以无副作用地采样未来时间。
其内部明确分成 `cycles * cycleDisplacement` 的周期基准及当前周期的关键帧插值，再将兼容比例、缩放和余数合并后才向零截断为 milli。
周期位移不按周期逐次舍入。实体用固定世界坐标基准加 `F(t)-F(anchor)` 计算位置，动作跳转或外部传送时重新建立基准。
Stinky 巧克力的最低速度采用 `RootMotionClamped`：逐源区间解析积分 `max(原区间速度, 最低速度)`，再按周期数和当前区间位置采样。
它不以 `max(累计原位移, 累计最低位移)` 替代积分；full-last 的末帧保持区间也参与最低速度处理。

累计位移由两个源关键帧插值，周期位移按完整周期数计算。每步都直接从基准求位置，不再累加 speed * delta。
周期末尾的不足一个像素不能通过逐周期取整丢掉。
整数碰撞坐标只在最终输出时按现有向零截断规则产生，不反馈到下一步；负数不能用 floor 替代向零截断。
外力位移、传送、换行等离散事件显式更新运动基准。

当前速度实现存在 N 与 N-1 的换算差别。首版以旧连续积分模型为兼容目标：
普通循环的根运动补上 N/(N-1) 的精确比例；full-last-frame 按原末帧保持处理。
这避免把当前速度采样误差修复与平均速度重新平衡混在一起。
这个兼容比例由编译器生成，不逐次用浮点计算。

`mVelX` 到动画速率的计算和基础随机速率继续保留原有 float 结果及取样时机。
冰减速等比例变更也保留 float 结果，不额外舍入到千分 fps。
只有用该速率建立整数纳秒周期时舍弃不足一纳秒的周期时长；同一事件时间轴及相同速率值下，任意更新拆分仍严格一致。

僵尸、保龄球、蜗牛、僵王火球以及附属动画同步中的 `_ground` 使用点一起迁移。
绘制用到的浮点矩阵、三角函数结果不回写权威运动进度。

## 动画事件和直接写相位的调用点

- 事件时间编译成动作内的精确阈值，按明确的半开区间判断跨越；单步跨多个周期逐个产生事件。
- 原 ShouldTriggerTimedEvent 的边界方向在实现前固定下来，不能复制目前漏掉多周期的判断。
- 使用明确整数比例或 `SeekRatio(float)` 描述主动 seek，一次转换到整数纳秒，不继续直接写 float 累加相位。
- 多头植物等同步动画复制整数播放位置；动作范围不同时进行明确比例换算。
- 轨迹快照、片尾字幕、主菜单云层和存档中的相位字段也必须迁移，不能只改僵尸。

## Particle v7

Particle 当前仍有：

- 参数节点的 float 时间、上下界及缓动/分布求值；
- 由纳秒 age/duration 派生的 float 归一化寿命；
- float 位置、速度、旋转、图像动画进度；
- float 发射数量累加器；
- 与更新次数有关的力场积分和随机震动。

v7 的 DSL 数字和源定义采用与 reanim 相同的浮点参数规则。
age/duration 继续以整数纳秒为权威，曲线求值使用 age/duration 比例，不将归一化寿命作为可变累加状态。
随机分布在粒子生成或指定事件时抽样，保存种子/抽样结果，不能因外层更新次数不同而额外抽样。

纯时间曲线按整数年龄/时长的 double 比例采样。常量发射率按有效发射时间的累计积分差确定数量和余数；变量发射曲线按当前主步取样并积分，允许不同分区产生差异。

按用户的后续裁决，取消独立 100Hz 子步。每次有效主更新仅执行一次发射器和粒子更新，寿命、交叉淡出、动画时间按实际纳秒推进；速度、加速度和旋转按实际时长缩放，摩擦按指数衰减。定位、抖动及角度曲线使用本次与上次采样之差，不重复乘步长。

出生初始化为 0ns，不额外执行一整步。生命周期比例使用完整时长，不扣一个固定 10ms 或当前步长。离散吸引、碰撞、限速、震动和随机力场仍是按步模拟，不再承诺跨步长分区位级一致，也没有为旧帧图数量设置物理频率上限。

## 存档与验证

新存档 v3.3（schema 10740）保存整数动画起始时间和时钟快照、植物期望发射时间、保龄球目标行到达时刻、弹射物创建与运动段起点、浮点速率、浮点角色坐标、double 根运动基准、匀速段的整数经过时间，以及必要的 particle 状态和随机状态；派生帧号和临时绘制浮点不重复保存。早期未发布的千分坐标布局 10736、相对时间布局 10737、角色绝对时间布局 10738 和固定粒子步长布局 10739 只作为转换器输入。
存档版本与定义 v7 分开命名，原版/v1/v2/v3.2/v3.3 的转换路径保留，游戏仅直接读写 v3.3。
旧 float 相位按固定规则量化为新 clock；旧浮点运算历史不可恢复，不宣称旧存档能还原“从新机制开始运行”的历史。

验收条件：

1. 两类 DSL 任意合法小数精度、float 范围、非法字面量、行号报错及生成常量位模式校验。
2. 同一累计纳秒，30/60/100/144/200/240/1000 Hz 和随机拆分的整数播放位置完全相同。
3. 同平台的根运动和最终 float 坐标逐样本位模式相同；与旧连续积分模型单独比较一次性纳秒周期量化差。
4. 正反向、暂停、非零起始相位、多周期大步、full-last-frame、动作切换、同步及存档续播。
5. 相同事件时间轴下，重动画时钟事件计数一致；常量粒子发射率在无寿命/容量限制的共同累计时长处具有一致数量。粒子的力场、碰撞和变量率不要求跨分区状态相同。既有布尔游戏事件消费者可能合并一次大步中的多次事件，不把时钟计数正确性宣称为全部事件分发一致性。
6. 性能分别测进度推进、轨道采样、根运动和密集粒子；不将整数算法默认当作更快。
7. Vulkan / Win7 OpenGL 的绘制回归、加载上传即弃、存档转换及读取回归。

实施顺序：数值解析与源迁移 → 静态定义 → 整数播放时钟/事件 → 根运动调用点 → Particle 主步时间/发射/力场 → 存档转换 → 双后端验证。
本方案按用户的实施指令执行；全游戏碰撞、输入采样和既有布尔事件分发不自动获得任意步长一致性。

## 弹射物与保龄球

弹射物移除未启用的帧号、帧数、选帧计时器、帧间隔，以及没有行为消费者的点击退避倒计时。普通弹体仍直接绘制图集矩形；火豌豆的附属 reanim 和各类附属粒子独立保留。

弹龄由关卡时间减创建时刻得到。运动段另记绝对起点时间以及 XYZ、旋转和阴影起点，使旧存档可以在当前位置接续运动，并在必要的离散事件处重新绑定；不再每步累计弹龄。普通弹道不增加目标坐标字段，发射端将瞄准结果转换为初速度。玉米加农炮原有的目标 X/行用于未来下降段，保留其信息，维持先升空、再切至落点上方的行为。

直线、星星、三发偏移、普通抛射及相关旋转从运动段起点和整数经过时间求值。普通抛射使用原 100Hz 先更新速度再更新位置的解析延拓 `v0*t + a*t*(t+1)/2`；这里只定义轨迹的参考单位，不要求逐 10ms 迭代。追踪弹随当前外层步进调整方向和坐标，不设固定 100Hz 子步，不承诺不同步长下轨迹相同。

保龄球横向仍使用 reanim 根运动，纵向用目标行到达时刻和 200 像素/秒求值，跨行时按到达事件处理行桶迁移和反弹。原 8 字节固定子步余数改存到达时刻，不增字段。普通坚果保留行中心附近的碰撞窗口；巨型坚果每次外层逻辑步进允许命中，直接伤害为 1,000,000，继续经过原僵尸伤害与免伤规则。

## 已接入的关卡时间轴

复用 `Board::mMainCounter.mNanoseconds`，不增加重复的关卡总计时字段。
生存无尽换轮调用 `InitSurvivalStage()`，不会清零此字段；重新选卡时战斗计时停止，恢复后继续。
完整 `InitLevel()` 才将它清零。

Reanim 使用“当前所属时钟时间减创建/段起始时刻”求局部时间。
对象单独暂停、减速或变速时保存当前局部进度并重设段基准。
倍速必须统一作用于模拟时间增量，相关定时器、积分器与事件检测消费同一个增量。
菜单、选卡及其他独立播放的视觉效果保留适合其暂停语义的时钟。

`mMainCounter` 在 Board 暂停检查之后、效果和对象更新之前推进并发布；
战斗未实际推进时不变。原来位于 `UpdateGameObjects()` 之后的推进已移除。
该字段改用 `MonotonicTimeCounter`，取消原版 `2^32 * 10ms` 的回卷。
其他旧 unsigned 计数器保留原语义。

主循环负责真实 `steady_clock` 与逻辑模拟时间的对应关系；对象不分别读取系统时钟。
存档只保存逻辑时间，读档时按当前运行时的时钟重新对齐视觉动画的纪元。
本轮不新增倍速 UI，也不更换原有更新步长策略。

## 植物发射截止时间

战斗中的发射周期改为绝对 `mNextLaunchTimeNs`，达到截止时间才消费事件。
下周期从原截止时间推进，保留跨步超出的时间。
`mLaunchClockSampleNs` 用于对象单独冻结时保持剩余时间；
`mLaunchWindowStartNs` 记录已处理的副发射事件游标，避免有界追赶后丢事件。
整局暂停时关卡时间不变，不移动这些字段。

随机间隔直接在原实际最小/最大时间之间按整数纳秒均匀采样；
组合游戏现有 MT 输出并拒绝短余数区间，消除取模偏差。
只在初始化或周期事件时抽样，不按外层更新次数重抽。
单次更新的事件追赶有界，未处理的截止时间保留到下一次。

原有 `mZenProductionCountdown` 槽在禅境花园表示倒计时，在保龄球表示碰撞次数；
两种业务互斥，不新增独立碰撞次数字段。弹射物轨迹改造另行讨论。
