# 性能优化原理与基准

本页按优化原理组织；每节先解释减少了什么工作，再列对应基准与测量边界。当前版与1.0未见明确提升的同口径指标只列当前值；改善明确且口径一致时保留1.0比较。细小波动不登记为新收益。完整历史原始记录继续归档，已退役路径不留在现行性能表中。仍生效的机制先例单独保留；没有新同口径测量时明确标注历史，不因删除旧夹具而删除优化原理。局部表缺少static属于本项目代码缺陷，修复记录见[修复总账](fix-ledger.md)，不列为原版路径的优化收益。

本页已归档数值以2026-11-01的v3.2.4测量构建为准；当前发行版不自动继承为“已复测”。保留仍有比较意义的1.0同口径数据；已退役机制只解释原理与历史边界，不重新包装成当前收益。

各表以所链接的构建哈希与测量条件为准；程序版本与存档格式版本分开记录，当前存档格式为v5.1。

“原机制模型”“原版代码片段编译”“原版EXE机器码”“当前生产函数”分开标明。不同范围不互相替代，ns/查询、整轮总耗时、CPU Draw和整局成本分别解读。

## 1. 将多段条件选择变成静态参数表

固定枚举到参数的映射可在编译期建表。一次范围检查和下标读取替代多段条件比较；常量数据集中存放，也减少重复业务代码。函数指针表适用于需要不同处理函数的情况，但间接调用本身有成本，不能据此推断所有switch或if-else都应替换。

### 连续粒子名册与附件平面遍历

历史粒子名册模型记录132.2→2.42µs/pass（900粒），已知槽删除模型801.5→550.3ns；它们是旧布局的历史模型，不能冒充当前184字节粒子完整更新。附件历史模型含particle/trail/reanim/other且下游为空桩，trail已退役，因此不恢复为现行混合负载指标。机制保留，旧数据与条件可追溯到[v2.0总账](https://github.com/YuHao2006/pvz_perf/blob/v2.0/docs/perf-fix-ledger.md)及[56项覆盖清单](../Tests/evidence/production-small-benchmarks-20261029/coverage.json)，不将历史模型复跑当成当前生产性能。

## 4. 合并GPU调用，减少动态数据与重复采样

bindless只减少纹理描述符切换，不会自动合并不同混合状态。Vulkan保留相邻同态绘制顺序，合并可兼容的提交，不按纹理重排半透明图元。

| 优化 | 已落地做法 | 作用范围与限制 |
| --- | --- | --- |
| 普通／additive合批 | 支持dualSrcBlend时统一双源精灵混合；不支持时使用独立管线 | 减少交替混合造成的断批，不减少特效或改变叠加顺序 |
| 透明边缘处理 | 普通图像上传前修补全透明像素RGB | 把原逐fragment邻域采样移出稳定绘制路径，保持alpha与线性采样语义 |
| 专用精灵shader | 直通输入走精简采样，生成图像／滤镜／覆盖率走对应路径 | 避免把字形或特殊输入错误套进普通路径 |
| 四顶点矩形 | 调用点直接提供四角，配静态16位索引 | 每矩形动态顶点从6×40字节降到4×40字节；不在提交期比较顶点去重 |
| 混合索引前缀与固定容量 | 纯三角形／矩形用静态索引，混合时才物化索引前缀；普通图片直接写最终四角顶点 | Vulkan每帧固定65536顶点，无分页或扩容；超过容量报错，包含最终呈现几何 |
| 状态复用 | 合批并复用未改变的管线、纹理和裁剪状态 | 不取消有业务语义的局部裁剪 |
| Vulkan 双槽帧资源 | 仅命令／同步对象与动态几何流轮换；复用前非阻塞检查fence，未完成跳过绘制、逻辑照常；所有纹理和渲染目标共用 | 桌面像素／生命周期／同步回归通过，手机整局收益未测；不据此宣称提升 |
| Vulkan 1.3 同步 | 图像／回读屏障改用 Synchronization2，帧、上传和图像批次使用 Submit2；呈现释放的目标阶段为 NONE | 场景回到颜色附件时按已知读写用途同步，不再一律 ALL_COMMANDS；尚无单项提速测量，既有整局数据不代表此改动 |
| 离线图集与上传 | 离线装箱、共享图集、上传后释放CPU解码数据，空上传队列立即返回 | 不把图集面积当作实测显存，不把60秒可行排布称为已证明最优 |
| 泳池 | CPU按行／列复用波纹求值，GPU绘制网格并生成焦散纹理 | 保持v3.2.3分工，与已撤销的reanim／particle GPU求值分开判断 |

同一个7687三角形的固定GPU夹具中，draw／管线绑定计数从1989到185，再到34；提交顺序和内容保持。它是调用结构证据，不是锁频提速倍率。[GPU专项](gpu-submission.md)说明实现、像素门槛及原始证据。

### 复用资源，缩小派生缓存

同一地图不再重复放入 Credits 图集。DSL 的 `shared-image` 在加载期绑定已有地图纹理；共享纹理统一放入全局表并按资源去重，表里不保存任何 reanim 专用图集。当前只有5个外部纹理指针；4个 Credits 定义用8个紧排的整数索引引用它们，普通图像槽不占这些表。编译器把外部槽排在各定义末尾，同时重排关键帧槽号与UV；普通定义的数据顺序不变。每个定义仍保留专用图集，普通 reanim 在渲染组入口读取一次外观纹理，轨道循环不查询外部表。x64静态定义为88字节，范围元数据利用对齐空隙；全局指针与索引合计72字节，不增加实例或存档字段。共享绑定、完整资源重载和14张Credits截图逐像素对拍均通过，见[全局外部纹理证据](../Tests/evidence/reanim-global-external-textures-20261114/README.txt)。

图鉴把三页完全相同的像素保存一份，差异作为补片，地面复用地图与冰道；大头贴静态界面离线烘焙并裁去透明边缘。逻辑尺寸和点击位置仍独立保留。普通卡牌用底板和植物预览；战斗／传送带在选卡结束后建立临时卡牌图集，退出关卡或生存换轮销毁。升级植物价格变化只覆盖对应卡片区域，不在每帧重建图集。

同口径全资源组显存夹具的一次候选运行中，空阵型无尽阶段的采样纹理需求由173.532降至169.712 MiB，池内实际使用由206.643降至203.354 MiB；64 MiB分块预留仍为256 MiB，不能声称驱动已分配显存同步下降。该夹具不是重负载无尽实战，不产生FPS收益结论；演员预览缓存仍保留。原始记录与像素证明见[资源候选证据](../Tests/evidence/vulkan-memory-candidate-20261114/README.txt)。

reanim插值、三角函数与particle模拟及绘制参数均在CPU；GPU只消费最终几何。颜色压缩、矩形实例、生成图像合批等未进入当前路径的试验不计入已落地收益；双槽主帧资源已落地。

DX12已接入普通精灵专用shader、normal／additive双源合批、四顶点矩形、静态16位索引与混合索引前缀，并复用提交暂存数组及未变的根常量。共享加载路径中的透明边缘修补同样生效。当前DX12场景目标仍为BGRA8：源RGB乘alpha前移到shader后会改变UNORM取整位置，四层叠加对拍容许累计4个字节级色阶差异；覆盖率字形仍保持精确比较。独立RTX 4070渲染检查包括80000顶点跨界拆批和混合图元，不能把检查通过写成已测提速倍率。[DX12验证证据](../Tests/evidence/dx12-gpu-submission-20261029/)。

OpenGL已接入下文的普通贴图硬件采样及状态缓存专项，功能验证见[OpenGL证据](../Tests/evidence/opengl-sprite-v3-20261029/)。帧资源轮换现已扩展到GL／WebGL、DX12及DX9：每个槽位的动态数据由其完成信号保护，主画面只轮询状态，忙时延期绘制而不阻塞逻辑；纹理仍共用。GL不再每帧glFinish，DX12的可写描述符也按槽位隔离，只同步变化的纹理描述符。资源上传、读回、销毁和尺寸变化所必需的同步仍保留。

Metal源码同样按双槽位组织，复用顶点和argument buffer，并使用四顶点矩形与静态16位索引；当前没有Apple编译环境或实机，不能视为已通过验证或已测提速。Web通过requestAnimationFrame让出执行权，避免绘制提交计数高于浏览器重绘节奏；绘制FPS仍不等同于屏幕实际呈现FPS。各后端验证边界见[本版说明](releases/v3.3.2.md)。历史DX12与当前Vulkan不用于量化单项GPU优化收益。

### reanim／particle：GPU化不可行，保留CPU求值

**本项目当前不采用reanim／particle的GPU化方案，按现有负载与实现判定为不可行。** 这里指把动画求值或粒子模拟搬到GPU；纹理采样、混合和三角形绘制仍由GPU负责，不是退回软件渲染。结论限定于本项目当前方案与已验证设备，不推断所有GPU架构或未来实现都不可能获益。

| 模块／方案 | 不采用的原因 | 当前运行路径 |
| --- | --- | --- |
| reanim在顶点shader内插值和计算三角函数 | 同一轨道的四个角点会重复求值；减少CPU工作未形成明确的整机功耗收益，不能把GPU busy或CPU占用单独当作能耗结论 | CPU定位整数相位、插值，并为每条轨道计算一次变换；四角复用，随后提交GPU绘制 |
| reanim每轨道先用compute生成变换基向量 | 虽消除了重复三角函数，但增加dispatch、GPU内存屏障及中间缓冲写入／读取；包含预计算与绘制的桌面GPU总计时未通过收益门槛 | 撤销预计算管线及中间资源，不在游戏中保留运行时切换或回退分支 |
| particle公式路径或完整GPU模拟 | 现行离散力场、随机参数、生命周期与交叉淡出依赖CPU状态；拆成多套路径会增加状态同步、排序及维护成本，当前不重新启用 | CPU按实际纳秒步长模拟并求绘制参数，GPU只接收已确定的几何与绘制状态；公式粒子保持退役 |

本轮重新测量的是reanim方案，没有取得新的particle GPU模拟对照数据；particle部分是当前工程取舍及已有路径撤销结论，不虚构新的粒子性能数字。相邻绘制合批、静态索引与透明边缘处理继续生效，GPU化撤销不等于撤销这些优化。

CPU侧使用FastSinCos，让同一角度的sin／cos共享一次角度归一化，再求两项多项式；reanim的两个skew轴各求一次，矩阵由四角复用。该改动不改变整数纳秒相位或存档布局，不据局部三角函数基准宣称整帧提速。

[原始样本](../Tests/evidence/v324-microbenchmarks-20261101/trig/)同时保留CRT、sqrt和pow诊断；后几项不是现行优化候选，不纳入收益表。


发射器系统渲染参数缓存未采用。它对同发射器的多粒子负载有局部收益，但单粒子负载会增加成本，实际效果还取决于改版的轨道和生命周期设计。为保持通用路径精简，已撤销缓存侧表、失效处理及专属测试，系统参数继续逐粒子求值；不在现行优化指标中登记该试验收益，存档格式未改变。

这轮试验原始样本已清理，只保留v3.2.3基线数据供后续同口径复测；本节保留方案结论，不登记GPU化收益。文档内已有的1.0／3.0正式历史基准不属于这轮试验数据清理范围。

## 5. 整数时间与相位求值：用CPU成本换一致性

共享纳秒时钟与出生／结束时间避免浮点时间逐拍漂移。reanim以整数时间定位相位，根运动用完整周期位移加当前周期插值，位置不从上一拍坐标累加。普通物件和粒子仍按实际纳秒步长模拟，复杂力场不强行公式化；公式粒子和运动指数采样表已退役。

目标FPS控制调度节拍，不等于把每次更新伪装成固定时长。单次逻辑更新消费实际积累的纳秒时间，不截成10ms，也不拆补拍；节拍余量用于安排下次更新，避免同一段时间被模拟两次。逾期不额外sleep，离散碰撞／力场精度允许随步长变化；reanim相位和根运动仍按共享时间求值，规则见[运行时](runtime.md)。

### 常值轨道短路

FloatTrackEvaluate在单节点且low==high时直接返回常量，跳过曲线选择、随机区间及插值工作；空轨道也保留直接返回。这个短路仍在Definition.cpp使用，与时间比例从哪里取得无关，不能因为删除旧代数夹具就省略其原理。旧3.90→2.75ns记录的锁定条件未确认，不作为3.0有效数值；寿命倒数乘则已被出生时间和侧表机制取代，不恢复成当前方案。

### 复用单次更新时间求值

粒子数据池以两张1024项double侧表缓存粒子与发射器的归一化年龄比例，不增加实例字段，由当前纳秒时间减出生时间求值后共享给物理轨道与绘制。初始化、循环、交叉淡出寿命变更及读档重建缓存；字段不序列化，没有浮点时间累加。附件轨道先求一次GetFrameTime，再将同一结果传给变换求值，避免重复采样和除法。

缓存的受控实测不支持“每种场景都更快”。当前真实完整渲染参数查询与冻结未缓存函数体对拍，不是原版EXE；每组min-of-5、单位ns/查询：

### 共享关键帧缓存：绘制、根运动和保龄球

Reanimation统一保存当前关键帧号、该关键帧的整数纳秒起点及整数帧时长。更新以整数除法／取模求跨帧数与余量，推进帧号／起点，保留本次更新越界的整数时间。同一更新时间的后续查询直接复用归一化快照。帧时长的小数纳秒固定舍弃，周期为整数帧时长乘区间数，各步长使用同一时间轴。不缓存帧时长倒数，插值处临时计算double(age)/double(framePeriod)。动画速率仍为float输入，不累加浮点相位。

GetFrameTime、RootMotion及坚果保龄球共用实例帧状态，避免反复以完整相位乘区间数再做整数除法。Reanimation在回绕时直接累加根运动基础位移，不记录累计周期；Zombie只保留世界坐标绑定偏移，不保存已消费周期或缩放乘积缓存。固定_ground直接定位。事件仅记录本次更新的回绕量，lastUpdate用于暂停与重绑；原版业务完成计数mLoopCount保留。旧mPhaseOriginNs删除。

正向跨帧直接定位，不使用while逐帧减法；倒放与回溯定位放到独立函数。倒放的帧内读取也使用缓存，原版潜水僵尸以-24播放anim_uptoeat的行为保留。冷路径不是取消功能或逐tick子模拟。

## 6. 整局结果：验证以上机制的共同效果
