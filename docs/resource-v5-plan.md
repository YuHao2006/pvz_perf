# reanim / particle 图集设计与 v6 外观扩展

状态：v5 图集设计现已扩展为 v6。离线打包、定义加载、图集区域及同一
compiled 内的共享行为与外观数组已落地；本文文件名保留历史引用，
协议见 [RESOURCE-V5-FORMAT.md](RESOURCE-V5-FORMAT.md)。完整游戏画面与性能仍需实测，
以下条目中的验收目标不代表已经取得对应性能收益。

## 已确定的目标

- 发行时，默认一份 reanim 或 particle 定义对应自己的图集；
  `.pvzbuild` 编译配置可以显式让多个定义共享一张图集，成员可以跨 reanim / particle。
- compiled 定义直接描述图集中的矩形区域，不再用全局 ImageSymbolId 定位图片。
- 只被 reanim / particle 使用的图片，只进入包内对应图集，不再单独加入运行时
  编号纹理资源表或保存一份独立运行图片。
- 被 UI、字体、游戏代码等直接使用的图片仍有独立的资源归属；
  不能只依据动画文件引用就把它们删掉。
- 图集在构建阶段生成，运行时只加载、绑定图集及矩形元数据。
  不增加运行时打包、源码图片驻留或测试插桩。
- 公共元数据用 public 字段，通过 const& 传递只读记录，不新增访问器。

## 资源闭包与所有权

构建工具需要分别建立定义图片集合和直接使用集合：

| 分类 | 发行策略 |
| --- | --- |
| 仅被 reanim/particle 使用 | 写入定义图集；不发行独立 PNG/JPG/alpha 配图或编号纹理描述符 |
| 同时被定义和 UI/代码使用 | UI/代码所需资源保留；图集内的使用按定义规则处理，报告重复像素成本 |
| 字体字形页及其 alpha | 由真实 compiled font 引用保护，不按文件名或 IMAGE_ token 粗略删除 |
| 动态生成、可写渲染图片、滤镜派生图 | 保留自己的生命周期，不写回不可变定义图集 |

资源表的自动生成声明、分组加载绑定不能被误判成游戏代码的真实使用根。
反过来，真实代码引用、字体引用、动态覆写及区域别名也不能被漏掉。
专用图片不在运行时编号表注册；离线作者数据仍可使用原有名字解析来源。

## compiled 区域信息

矩形至少要区分：

- 图集中的实际像素区域。
- 原始逻辑宽高及裁剪/偏移信息，避免打包改变角色位置、粒子大小或鼠标区域。
- 粒子条带的 rows / cols / frame 语义，不能把整张图集尺寸当作单帧尺寸。
- 透明边界和滤波所需边缘扩展。

相同区域在一个定义内反复使用时，在定义内去重；共享组按源图片符号合并图片。
每份定义持有图集的共享所有权，轨道和发射器直接记录编译器写入的矩形；
compiled 中没有全局 ImageSymbolId、局部图像编号或图集路径。
加载程序通过生成的绑定表给每份定义的图片指针赋值。当前字段布局
见协议文档，由编译器和加载器共同遵守。
现有容器/元数据标记应明确分派，不能让旧 symbol 载荷误读为矩形。

文本/字体轨道、无图轨道、精确 fullscreen 轨道、动态图像覆写等行为保持独立，
不为图集化改写动画语义或绘制顺序。

## 打包与兼容边界

- RGB 与独立 alpha 在离线阶段按现行组合语义处理，验证颜色与透明度等价。
- 不旋转子图；先保证像素与矩形的直接映射。
- 透明图集子区需要边缘扩展和区域采样限制，防止线性过滤串色。
- 严格保留现行 mipmap、repeat、色彩空间和混合行为；不能一概改成整图
  CLAMP 或把某一个子图的边缘延伸到其他子图。
- 每个定义只对应一个图集时，超过目标后端最大纹理尺寸、无图片的定义以及
  跨定义共用图片的策略要明确，不能静默拆成多页或悄悄恢复独立编号图片。
- 稳定生成顺序和打包算法，记录源像素、派生图及 compiled 的校验信息。

编译入口为 `assets/definitions/ResourceBuild.pvzbuild`，分别选择定义文件、
设置装箱参数和声明共享组。原聚合 import / forward DSL 入口已移除。
原生 MaxRects 提供可行布局，再由离线 CP-SAT 最小化图集面积；
`AtlasSettings` API 默认仍为不限时、`require_optimal true`，要求证明固定朝向、
既定边距和尺寸上限下的全局最小面积。pea_family 持续求证超过三小时仍未证明后，
用户明确授权生产配置切换为每图集 `time_limit_seconds 60`、
`require_optimal false`；当前 `.pvzbuild` 显式保存这一覆盖，不改变 API 的严格默认。
60 秒是每个装箱单元的 CP-SAT 求解预算，不是全资源构建总时限。

两种模式都必须使用 exact 求解器，MaxRects 仅提供初始可行解。
严格模式只接受 `OPTIMAL` 或有效的 `LOWER_BOUND_PROVEN`，要求下界等于图集面积；
显式限时但仍要求最优的图集若超时未证明，构建仍失败。
放宽模式必须同时声明正的有限预算，且不超过 86,400 秒，允许超时后发布经过几何验证的
最佳 incumbent。`FEASIBLE`、`UNKNOWN` 必须保持 `optimal false`；
`UNKNOWN` 可使用未被求解器改进的原生或检查点可行布局，不得据此声称全局最优。
即使选择放宽，若结果标记为最优，也必须满足完整的证明元数据检查。

发布前先验证矩形朝向、尺寸、边距、边界与不重叠，再独立检查配置策略与元数据：
模型和求解器版本必须匹配，状态必须有效，面积必须等于实际宽高乘积，
下界必须在零与面积之间，gap 必须如实等于 `(面积−下界)/面积`。
错误状态、虚假最优标记、不一致的面积/下界/gap 或无限时的放宽配置均不能发布。
旧可行解缓存只作验证后的几何提示，不继承其证明。
全部图集通过各自配置策略前保留原有生成头和资源包；构建报告保留状态、下界、
gap 与最优性结果，并提供 CP-SAT 日志、离线求解进度和可行解检查点。
Python 负责建模和产物协调，耗时搜索由 OR-Tools 的原生 C++ CP-SAT 引擎执行。

OpenGL / DX9 已删除加载期装箱和运行时图集页面管理，
各后端通过公共加载路径直接上传编译期生成的完整图集。
绑定层采用图集的物理存储，逻辑宽高、UV、clip 等仍按子图处理。
定义持有共享的 GPU 图集图片，轨道和发射器只保存矩形与条带网格；
不为每个区域创建 MemoryImage 或 GPU 纹理视图对象。
PNG 解码数据仅用于主线程上传，完成后释放。

## 性能验收

图集减少纹理切换有利于旧式绑定路径，但不能把这一点直接换算为 bindless
路径的收益百分比。Vulkan / DX12 已经使用描述符数组，需要单独测量；
按定义打包也可能增加跨定义重复图片的显存与包体。

验收使用独立测试和已有外部观测工具，不向正式游戏添加帧计数探针或日志：

- 对相同画面的像素、alpha、clip、混合和动画轨道结果做回归。
- 分别测 Vulkan、DX12、OpenGL、DX9 的 CPU 绘制与 GPU 帧时间。
- 记录纹理/图集数、驻留字节、包体、装载耗时、打包利用率和跨定义重复像素。
- 不能仅凭 draw call 变少认定更快，也不能仅凭 bindless 已有批处理认定图集无收益。
