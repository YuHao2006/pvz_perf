# 网页存档：共享云档与直接 IndexedDB

更新：2026-11-17。实现已同步 main 与高清分支源码，尚未发布到 Toy；不改变 DAT64 二进制格式。

## 共享空间与旧云档

网页配置的 `sharedStorageId` 为 `st_v1sneoksfl8xqth1`。用户资料和阵型库使用各自命名空间，调用官方 `getSharedStorage`／`setSharedStorage`／`removeSharedStorage`。

玩家打开**原 Toy 的更新版本**时，先读共享空间；对应共享索引为空才读取该 Toy 原有私有云档。分片、摘要、解压大小及内容完整校验通过后，先复制数据、再提交索引。原私有云档保持不变。迁移期间若共享空间已出现存档，停止迁移并重新读取共享档。

这不是一次服务器端全玩家批处理。尚未打开新版的玩家不会立即迁移；全新 Toy 无权直接读取另一个 Toy 的私有数据，因此原 Toy 也需要部署这段迁移代码。SDK 不会代为自动迁移。共享空间仍按 B 站登录玩家隔离，不让不同玩家读取彼此存档。

## 防止旧进度覆盖

- `modifiedAt` 表示内容修改的时间；`savedAt` 仅表示上传时间。等待网络、重试、恢复云档都不把旧内容伪装成刚修改的进度。
- 启动、开始游戏和正常 Quit 时自动比较时间；较新的云档覆盖本地前，保留冲突备份。旧格式使用 savedAt；同时间或无有效本地时间时优先已有云档。游戏运行中不直接覆盖正在使用的用户资料，退出后再同步。页面不再提供手动上传／恢复云端按钮。
- 上传前重新读取云端；发现较新版本或基线变化则停止。上传数据后、提交索引前再复查一次。
- 每次上传使用独立分片名，避免两个设备覆盖彼此正在写的分片。索引最后提交；正常保留当前版本及前一个版本，下次上传分配新分片前清理更早版本，避免长期累积占用键数。
- 数据不变不上传；每种存档最多保留当前上传和最新待上传快照，不积压每一次中间写入。限流错误按退避重试，没有云端轮询或逐帧网络请求。

官方接口未提供可用的原子比较并交换／条件提交功能。客户端检查不能彻底消除最后一刻的并发竞争，也无法完全解决设备时钟不一致。不能宣称“绝不回档”。索引与摘要防损坏，冲突时保留本地；关卡 DAT64 不由用户资料云同步覆盖。

## 本地直接 IndexedDB

新数据库 `pvz_perf_local_saves_v1` 的 `files` 保存文件字节和修改时间，`meta` 保存迁移标志。首次启动读取旧 `/persist` IDBFS 数据库，在同一事务中导入全部文件并提交标志；并发迁移会在写事务内复查标志。事务失败不标记完成，下次可重试。旧数据库不删除。

之后不挂载 IDBFS。启动时从新数据库恢复文件到 MEMFS，保持 C++ 现有同步文件接口；`/persist/development-v331/` 只是逻辑路径。写文件关闭后将该文件排入 IndexedDB 事务，删除和改名也同步；正常退出与设置保存只等待已变更文件的事务，不重新读取并复制整个存档目录；手动重试才完整扫描。修改时间调整直接更新待写记录。显式保存会等待事务完成。失败保留待写数据和先前已提交版本，提示重试／导出。支持的浏览器请求 `durability: strict`，不支持该选项时退回普通事务。

点击开始时申请 `navigator.storage.persist()`，结果写入运行诊断。拒绝或不支持不阻止游玩。持久许可减少浏览器在存储压力下自动清理的风险，不能阻止用户清除网站数据、隐私模式销毁数据或系统故障。隐藏页面只尽力刷新已排队数据，不能依赖页面关闭时才提交。

当前 main 普通读档不会删除关卡文件；真实删档仍会持久化，避免重开、通关或用户删除后旧档复活。本轮没有新增定时战斗快照：游戏尚未序列化的实时状态不在保证范围内。

这项改动改善持久性及写入范围，**不代表已解决全部内存副本**。为兼容同步 C++ 文件读取，当前启动仍把存档文件装入 MEMFS；数据库连接不另外永久缓存一份所有文件字节。大资源包、Wasm 线性内存和 GPU 纹理的占用也不会因此消失。按关卡异步调入、退出后释放需要另行改造文件访问入口。

## 完整关卡云档容量调查

2026-11-17 从官方发布平台 SDK 文档当前前端资源核实：普通云存储最多 128 个键，值为字符串且最多 1024 字节；共享接口列出的 key/value 约束与云存储一致，未单独说明共享空间是否有更大的总键数额度。因此不能把“共享”理解成大文件云盘。

实测现有完美／无尽测试包的 `game1_58.dat64`：

| 编码 | 字节数 |
| --- | ---: |
| 原始 DAT64 | 673,781 |
| gzip 9 | 141,421 |
| gzip 后 base64 | 188,564 |
| Brotli 11 后 base64 | 166,748 |
| LZMA 9 后 base64 | 166,216 |

即使采用这些更强压缩，这份测试档仍超过按 128×1024 字节估算的总容量，还没有预留用户资料、阵型、索引及安全更新空间。小档技术上可分片，大档和多档无法保证容纳。**本轮不启用完整关卡云同步**，保留直接 IndexedDB 和 DAT64 导出；需平台明确共享总额度或提供大文件接口后再接。

来源：[官方 SDK 文档](https://www.bilibili.com/toy/publish/sdk)、[官方共享存档 FAQ](https://www.bilibili.com/opus/1241171666570051585)、[IndexedDB 事务持久性](https://developer.mozilla.org/en-US/docs/Web/API/IDBDatabase/transaction)、[浏览器持久存储申请](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/persist)。SDK 文档的前端源码已在本地验证目录留存，未把第三方整页源码加入 Git。

- `test_shared_storage.mjs`：旧档迁移、已有共享档优先、校验失败不迁移、时钟冲突、旧上传拒绝、并发分片隔离、旧版本清理、恢复时间保持。
- `test_lineup_storage.mjs`：阵型增删、空库、迁移、跨设备冲突与命名空间隔离。
- `test_local_save_storage.mjs`：使用测试依赖 fake-indexeddb，覆盖首次导入、文件关闭提交、刷新、读取、删除、改名、事务失败重试、持久申请拒绝。依赖只装在本地 `out/verification/browser-storage-deps/`，不进入游戏包。
- 本地无头 Edge 使用实际 Wasm 文件系统和真实 IndexedDB：预置旧 IDBFS 存档，启动迁移成功；直接 `FS.close` 写入后刷新可恢复；`unlink` 删除可持久化；两次启动均准备就绪且无页面异常。

尚未在正式 Toy 宿主验证该共享标识的读写权限；CLI 的共享空间管理接口返回 404，不据此判定标识不存在。未上传或改写玩家线上存档。

## 2026-11-17：普通版网页内存实测

使用普通版无损 PAK、包内完美用户及无尽档，在独立无头 Edge / WebGL 环境中读取实际 MEMFS backing buffer 和 mmap 返回值。数字不是进程 RSS，也不含 GPU、解码临时内存、音频等其他占用。

| 项目 | 启动前 | 资源加载完成 |
| --- | ---: | ---: |
| `/persist` 文件逻辑字节／MEMFS 数据容量 | 674,699 | 674,911 |
| `/main.pak64` MEMFS 数据容量 | 39,209,797 | 39,209,797 |
| PAK 的额外 mmap 分配 | 0 | 39,209,797 |
| Wasm 线性内存容量 | 134,217,728 | 193,331,200 |

存档容量约 0.64 MiB；PAK 每份约 37.39 MiB。PAK 的 MEMFS buffer 与 Wasm buffer 不同；mmap 返回 allocated=true，确认另一份复制进入 Wasm。mmap 已包含在线性内存容量里，不能把上表四行简单相加。相同文件引用同一个 ArrayBuffer 时也不能重复计数。

IndexedDB 的磁盘数据不等于另一份永久 JS 文件缓存。本轮改为直接 IndexedDB 后，仍将存档装入 MEMFS；不会仅因取消 IDBFS 挂载就节省所有存档内存。更进一步需要按关卡调入，退出后释放不再需要的文件。

优先优化候选是网页 PAK 的双份保留：2× 高清 PAK 123,729,310 字节，4× 为 519,013,350 字节，若使用同一预加载／mmap 路径，重复副本的风险远大于示例存档。以上高清数字是包尺寸与路径推算，不是高清浏览器 RSS 测量。

不能在加载完成时直接销毁 PakInterface 或原包映射：条目仍以映射指针为读取来源，后续资源组和重进游戏可能再次读取。可研究保留一份可复用包数据、消除 MEMFS→mmap 复制；或用磁盘缓存配合异步按需读取。这两种都需要处理 Wasm 内存增长、映射所有权、退出再进入和后续读包。WebAssembly.Memory 释放内部 malloc 后通常也不会缩小已增长的线性内存容量，因此不能把 free 等同于立刻降低进程内存。以上为改造前测量。后续已完成网页单副本移交：Wasm 实例持有一份包，校验后移除 MEMFS 源文件，退出后复用。四种组合的增长／重启及坏包测试见 [验证记录](../Tests/evidence/web-pak-single-copy-20261117/README.md)。首次加载的临时峰值尚未优化。

网页使用黄色提示提醒玩家从游戏菜单正常 Quit，并等待红色上传提示消失；直接结束进程、关闭或刷新页面可能中断用户进度同步。Object.hasOwn 在模块初始化时选择原生函数或旧浏览器兼容函数，不在游戏每帧路径增加判断。
