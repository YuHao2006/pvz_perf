# 时间驱动改造与曲线接口变更

日期：2026-10-24。此文记录本地工作区的改动和验证状态；不代表 GitHub 发布。

## 本地检查点

`ce93db2` 是开始后续曲线与粒子改造前的 WIP 检查点。它包含此前已经完成双后端验证的角色时钟、弹射物、保龄球改造，也包含尚在进行的曲线接口和调用点迁移。它是可恢复的工作快照，不应视为可发行构建。

## 关卡与动画

复用 Board 的整数纳秒时钟。Reanimation 使用共享 Battle/Visual 时钟以及绝对起始时间，速率变化保持局部相位连续；正常循环将起点归一到当前周期。全局暂停停止时钟，不逐对象调整起点。单对象暂停、时间域绑定和读档恢复仍处理其局部基准。

主关卡时钟不再按旧的 32 位计时单位回卷。关卡时间与宿主 steady_clock 的对齐仍由既有主循环完成，存档不保存宿主时钟 epoch，也没有新增倍速 UI。

植物发射保存期望发射时刻，过期周期从上一 deadline 向后推进。随机发射间隔直接在整数纳秒区间抽样。尚未完成的攻击不会因追赶 deadline 而重复重启动画；单次更新追赶周期有明确上限，不能据此承诺任意大步长补演全部历史攻击。

## 弹射物

移除 `mFrame`、`mNumFrames`、`mAnimCounter`、`mAnimTicksPerFrame`、`mClickBackoffCounter` 和累加弹龄 `mProjectileAge`。这些选帧字段没有在正常游戏中启用；普通弹体仍绘制静态图集矩形，附属 reanim、粒子独立保留。

弹龄从关卡时间减创建时间取得。当前运动段保存独立绝对起点，以及 XYZ、角度和阴影起点。第二个时间锚用于旧存档从当前位置接续以及加农炮阶段切换，不是逐步累加的 elapsed。

直线、星星、三发偏移、抛射等使用起点和经过时间直接求值。抛射使用与原 100Hz 先更新速度再更新位置顺序相符的解析延拓；参考单位不要求运行时按 10ms 迭代。追踪弹按当前主逻辑步长转向、移动，允许不同步长产生不同轨迹。

普通投掷物不增加目标位置字段。玉米加农炮原有的目标 X/行用于未来下降段，保留必要信息，维持先升空、再切到落点上方的行为。传送门平移运动起点，不重置出生时间；屋顶补偿由绝对地形高度差计算。

`mX/mY` 碰撞缓存继续保留和同步，避免重现零坐标、不可碰撞的回归。

## 保龄球

取消固定 100Hz 子步。横向采样动画根运动；纵向按目标行到达时刻、地形行距和 200 像素/秒求值，跨行时处理到达事件、行桶迁移及反弹。

原 8 字节固定步余数改存目标行到达时间，没有增加成员。碰撞次数继续与 ZenGarden 生产倒计时互斥复用原辅助槽。

普通坚果保持行中心附近的命中窗口；大步跨行由到达事件补足。巨型坚果每次主步允许命中，直接伤害为 1,000,000，不增加命中冷却，继续经过原有伤害和免伤规则。

## 曲线接口

完整的迁移前调用清单见 [curve-callsite-audit.md](curve-callsite-audit.md)。其中 173 是静态源码调用点数量，不是每帧调用次数。

- 真正的时间动画使用 `TodAnimateCurveNs`，输入为 `int64` 纳秒。先计算整数差，再形成局部 double 比例；绝对时钟不先转换为浮点。
- `TodAnimateCurve` 与 `TodAnimateCurveFloat` 处理距离、计数、坐标、百分比等普通数值区间，输入改为 double，不再通过 int 截断。
- 删除浮点时间入口 `TodAnimateCurveFloatTime` 和没有额外行为的 `TodCurveEvaluateClamped` 转发层。
- 曲线输入与多项式中间运算使用 double，最终坐标、透明度等浮点结果仍为 float；整数输出保持原有最终舍入。正弦曲线保留既有 FastSin 渲染近似。
- 正反区间、端点钳制、回摆族端点行为保持明确。零时长区间定义为一个立即完成的 step。

这里退役的是曲线运行时入口中的旧 tick 投影。离线源定义或场景作者常量的固定时长单位不是当前 TPS；它们在边界转换为整数纳秒。历史存档的旧单位仍由离线转换器识别。

普通钱币和阳光的下落、收集吸附依然采用现有逐步积分；本轮只迁移其奖励动画、淡出和弹体缩放的曲线计时。固定目标收集的指数式、动态目标重绑定、落地事件等后续迁移点见调用审计，不宣称这些积分已自动获得分区一致性。

## 粒子

固定 10ms 子步已删除，每次主更新按实际 `deltaNs` 推进一次。摩擦按指数衰减，加速度、位移和旋转按实际时间缩放；定位和抖动更新使用采样差，不重复乘步长。出生初始化为 0ns，没有隐藏的整步推进。随机初始年龄直接在纳秒时长上取样。

常量发射率使用累计有效发射时间的精确积分差，发射时钟跨寿命循环保留。有限寿命和淡出截止限制可发射时间，已结束的淡出源不会恢复发射。位于同一系统其他发射器中的新淡出目标，由本步开始时的粒子 ID 快照排除，避免重复更新。

出生和 OnDuration 事件在主步末端处理，新目标从 age 0 开始，不递归补跑余下时间。循环寿命保留超出部分。离散吸引、碰撞、力场、变量率和随机采样允许在不同步长下产生不同轨迹；事件采样相对连续时间最多延迟一个主步。不再承诺整个粒子状态在不同更新分区下位级相同。

存档仍为 v3.3，内部 schema 为 `0x10740`，游戏只直接读取当前布局。转换器将此前 10736–10739 的测试布局升级到当前版本。ParticleSystem 精确尾部由 12 缩为 4 字节，仅保存 RNG；Particle 由 36 缩为 28 字节，删除重复当前年龄；Emitter 仍为 40 字节，将原当前采样槽改为累计有效发射时间。旧真实年龄、历史采样、发射余数和随机状态保持，旧固定步余数不再保留。

## 验证状态

曲线与粒子后续改造开始前，Vulkan/Win7 OpenGL 的 Release、真实生命周期、存档保存重读、全部弹射物图集绘制测试均通过。保龄球覆盖不足 10ms 的更新、单步跨多行、非固定地形行距及巨型坚果每步伤害。

当前曲线和粒子改造已完成统一验证：

- Vulkan 和 Win7 OpenGL Release 全部构建成功，分别通过 9 项和 10 项相关 CTest；OpenGL 额外包含 Win7 硬导入检查。
- 两后端真实生命周期的完整、缺失、损坏和错误尺寸图像场景通过；真实曲线函数覆盖 1ns、大 epoch、正反时间段、零时长、全部曲线端点及整数输出舍入。
- 生产粒子测试覆盖 8 种更新分区、常量发射总量、极长时间积分、摩擦、寿命、循环余量、零时长/暂停、淡出及新旧发射器目标，允许的步长依赖已单独测试。
- 两后端完整存档读取、保存和重读通过；同时比较读档后继续推进粒子 17,123,457ns 的状态，以及弹射物继续运动的结果。
- 两后端真实字体、按钮、粒子外观与全部 14 类弹射物图集绘制测试通过；PUFF 额外覆盖非旧 tick 对齐的年龄。
- 370 项 Python 工具测试均获得通过结果：首次发现 36 项缺少原生编译器环境而跳过，补齐环境后对相关模块补跑 57 项，全部通过，覆盖此前跳过的 36 项。
- 夜晚音乐高潮、渐变、释放和重触发在 30–1000Hz 测试通过，实际随附音轨解码检查通过。
- 两个 Release 的 `perfect-save-v3.3.zip` 已重建为当前布局，没有覆盖用户实际存档。两个 PAK64 仍为 642 项，SHA256 保持 `58444F294A2A03B94708CCFF613F33BAA3B52C8FBC22B3EB130C6EAEF7DF20F7`。

自定义测试日志和 fixture 临时输出均放在系统 Temp；构建系统自己的标准测试记录仍由 CTest 管理。未操作游戏 UI、未结束用户游戏，未推送 GitHub。

没有测得完整帧耗时前，本改造不被描述为已经提升性能。时间表示和生命周期结构变化也不等于全游戏任意步长完全一致。
