# Vulkan与DX12 GPU提交与采样

本页维护已落地的GPU调用结构、正确性边界和证据，不按日期追加试验过程。整局FPS／CPU结果统一见[性能优化与测量](perf-fix-ledger.md)。独立实验的GPU区间不等于整帧，也不能据此推导手机整机功耗。

## 执行边界

reanim插值、三角函数、顶点变换，以及particle模拟和渲染参数在CPU求值。GPU接收完成变换的图元，执行纹理采样和混合。动画常驻GPU、公式粒子GPU求值及其上传格式已撤销。
Vulkan 泳池波纹在 CPU 按行、列复用正弦结果，生成 96 个最终位置／UV／透明度顶点；索引拓扑保持不变。顶点追加到当前帧映射流，避免三层水面或 Credits 的多次绘制互相覆盖。水面 vertex shader 只做坐标投影及属性传递，不接收时间，也不计算三角函数。其他后端的水面几何路径暂未迁移。

水面保存不进入存档的 `mBirthTimeNs` 与已发布采样时刻 `mSampleTimeNs`；相位由两者之差求值，不累加经过时间。Board显式传入关卡时间，Credits与图鉴传入各自Visual时间，同时给出本次允许推进的纳秒数。战斗水面与闪光都随Board冻结，寒冰菇另有冻结规则。冻结及未更新的场景间隙平移出生时间，恢复后不补算冻结时间；同一时刻的重复更新不推进两次。原有暂停／冻结条件保持。波纹角度直接从纳秒相位求值；各后端使用 `SetCausticsTimeNs` 接收整数纳秒，CPU 直接以整数运算求出焦散查表所需的三组定点坐标偏移，GPU 只接收坐标；不再接收旧更新计数或浮点时间。焦散仍由 GPU 根据固定源纹理和定点双线性查表产生，没有随机数或前帧反馈。整数采样及 8 位透明度仍有量化，不能称作严格连续输出。这次改动没有存档格式变化；性能收益待同场景实测。

## 合批与混合

bindless纹理数组减少描述符切换，不自动合并blend状态。支持dualSrcBlend时，普通精灵和additive精灵使用同一双源管线：普通混合保留目标RGB的系数为1-alpha，additive为1，目标alpha维持原有规则。相邻兼容图元按原顺序合批，不按纹理排序，不减少特效。不支持双源混合的设备继续使用各自管线。

直通图像走精简精灵shader；生成图像、颜色滤镜、覆盖率字体等输入保留各自语义。不能为减少draw把字形或滤镜强塞进普通采样路径。精灵采样参考PvZ-Portable，同目录保留其许可证；双源混合及alpha保真是本项目实现。

同一个暂停读档确认页、7687个三角形的历史结构对照如下。这不是本轮11x性能结果，也不是锁频提速倍率。

| 管线状态 | draw／管线绑定 | 普通精灵输入段 | 通用输入段 |
| --- | ---: | ---: | ---: |
| 普通与additive分离 | 1989 | 2999 | 188 |
| 双源直通精灵 | 185 | 2999 | 188 |
| 普通图像透明边缘预处理 | 34 | 3164 | 23 |

三阶段场景内容和图元顺序守恒，后两行输入段总数相同。draw是合批后的实际调用，不等于C++输入片段。[计数与构建证据](../Tests/evidence/android-gpu-submission-20261027/manifest.json)。

## 透明边缘处理

全透明像素的RGB会参与线性过滤。普通资源在上传前修补其邻域颜色，保持alpha及可见RGB，避免每次fragment重复执行邻域纹素读取，并使其满足直通精灵条件。生成图像与特殊过滤路径继续遵守自己的采样规则。

这项处理并非本项目发明。原版1073英文零售程序SHA256为`5f650f52d12751e08b63e590edb0d9b9f09d087cea900baa0eb39e4af8eda251`，`0x0051CFD0`为修补入口，`0x0051CE20`求邻居颜色，绘制路径在`0x0051C983`检查标志并于`0x0051C991`清除。原版存在首用惰性处理及其他预处理调用，不能说它每个fragment都执行或全部严格在初始加载完成。[反汇编证据](../Tests/evidence/android-gpu-submission-20261027/retail1073-transparent-edges.txt)。

处理仍在加载／上传期，不固化进发行PNG。后续本机分辨率scale缓存应先缩放再修补，以保持发行资源统一；缓存键需要覆盖源内容、缩放和处理版本。目前不宣称该落盘scale缓存已经实现。

## 色彩滤镜直接求值

洗白类滤镜保持色相，只缩放饱和度和亮度。Vulkan 通用 shader 直接缩放 RGB 相对旧亮度的偏差，比例为 `saturationScale * min(newL, 1-newL) / min(oldL, 1-oldL)`；省去色相提取、三个通道的归一化和六分区重建。透明度、逐纹素处理后再过滤的顺序、字节截断及原有混合规则保留。

生成的 RGBA16F 图片可以超过归一化范围，因此分子、分母保留符号，并保留旧 HSL 重建值非正时返回黑色的边界。归一化 RGB 的两种滤镜分别穷举 16777216 个颜色，另各抽查 1000000 个正值 HDR 输入，CPU 浮点参考的最大通道差异为一个字节色阶；GPU 回归覆盖 nearest／linear 的原图与缓存别名、透明边缘及 HDR 黑色边界。没有新增逐帧 CPU 状态或存档字段。

手机高压场景的短窗口时间戳、必要 fence 等待与 CPU 原生采样作为定位证据保存，不代替锁频整局基准。额外白色遮罩快捷路径未显示可分辨收益，未保留。[场景与验证记录](../Tests/evidence/android-pressure-20261030/manifest.json)。

## 顶点、索引和状态

普通矩形、图片，以及未裁剪贴图从调用点提交四个顶点，不在后端比较六个顶点去重。当前顶点40字节，每矩形动态数据由240降为160字节；顶点颜色压缩和矩形实例仅属独立实验，未混入正式结构。

纯三角形和纯矩形使用初始化一次的静态16位索引；同批混合图元时才物化此前的索引前缀并追加后续索引。裁剪后实际三角形与矩形可以进入同批，不因图元种类切换断批。索引限制每个draw的局部地址；超过65536个顶点按完整图元拆分，以baseVertex访问后续顶点，不能回绕。底层缓冲区维持原设计，65536不是整帧或整缓冲容量。[16位索引证据](../Tests/evidence/vulkan-u16-20261027/)。

合批期间复用未变化的管线、采样和裁剪状态。必要局部裁剪必须保留，尤其是标题草坪展开、种子包冷却遮罩、文字／列表区域。空绘制早退与业务裁剪不是一回事。

## 同步和资源生命周期

Vulkan 当前轮换两套主帧命令池／命令缓冲、acquire 信号量、fence 及 CPU 写入的动态顶点／索引流。仅在复用同一槽位前等待其上次提交；不在本次提交后立即等待，也不要求另一槽位先完成。静态索引、所有素材纹理／图集、场景渲染目标、焦散目标、缩放链和只读定义仍共用，不复制图片资源；同队列已有屏障串联共享目标的写入和采样。每套流按需分配，常规额外一页约 8MiB 顶点和 0.6MiB 动态索引，超页继续沿用原有扩容设计。读回、修改共享资源及离屏操作仍排空主帧；纹理与描述符槽按提交序号延迟回收，完成序号只单调前进。桌面原生渲染回归验证两命令缓冲交替、纹理数量不变、连续帧像素、延迟释放和窗口重建，零 Vulkan 校验错误。手机整局收益尚未重测，不能由此宣称已改善帧率。[双槽验证](../Tests/evidence/vulkan-two-frame-20261030/manifest.json)。

Android把SUBOPTIMAL_KHR当作可继续呈现的状态，仅OUT_OF_DATE_KHR请求交换链重建；尺寸判断比较当前drawable查询值与创建时drawable值，避免旋转和表面范围导致每帧重建。当前600高交换链由系统缩放，仍有场景采样到交换链的present pass，不描述为已合并的直接绘制路径。

场景保留dirty-region需要的LOAD语义；DONT_CARE、矩形实例、生成图像通用合批、32位大批索引等试验不能列为已经交付的优化。

## DX12适配范围

DX12普通直通贴图使用独立片元入口，normal与additive通过顶点内部标志和双源混合合批；字形覆盖率、生成图像、滤镜与延迟边缘修补继续进入通用路径。目标alpha保留DX12原有的普通／additive累积规则。共享资源加载路径在上传前修补普通图像透明RGB，不新增发行素材格式。

调用点向DX12提交四角矩形，动态顶点从每矩形240降为160字节。纯三角形／纯矩形使用静态16位索引，混合时才生成索引前缀；局部顶点数达到65536时按完整图元拆批，保留8MiB映射页设计。提交暂存纹理数组复用容量，未变的根常量与索引缓冲绑定不重复提交。主帧仍使用单套资源，复用前等待fence。

DX12场景仍是BGRA8目标，双源路径在shader内先乘alpha会改变UNORM取整位置。四层normal／additive叠加对拍允许累计4个字节级色阶差异；字形覆盖率65536组合仍精确一致。独立测试还覆盖80000顶点跨16位边界、混合图元前缀、销毁后提交、离屏合成、泳池与缩放。RTX 4070测试报告D3D12调试层0错误，[记录与构建哈希](../Tests/evidence/dx12-gpu-submission-20261029/)。这些检查不提供CPU／GPU提速比例；OpenGL、DX9、Metal的专项移植尚未进行。

## 验证和性能口径

当前Windows实际图像夹具覆盖全部资源分组、字体、上传即弃、共享纹理生命周期、reanim外观和293个CPU粒子绘制情况；种子包冷却的四分之一／一半／四分之三边缘、商店翻页和Quit布局也纳入回归。检查通过证明对应画面／生命周期，不等于测得速度提升。

独立GPU实验用timestamp只覆盖指定GPU指令区间，排除CPU构造、读回及WSI呈现；像素对拍与同步校验单独运行。频率未锁定时不登记提速倍率，不从桌面独显推导Adreno、核显或手机功耗。[桌面实验证据](../Tests/evidence/desktop-gpu-sprite-20261027/)。

普通游戏构建已删除临时GPU查询池、每120帧工作量统计、imgstats及CPU分段计时。独立实验目标的计时宏保留，但不进入Release。Android既有状态和错误诊断不用于替代正式GPU采样。

手机系统刷新模式、游戏draw计数、SurfaceFlinger呈现和GPU timestamp是四种指标。监控叠加层可能影响调度，必须明确监控状态及频率条件。只有设备实际采集才能判断整机能耗，当前没有手机功耗结论。
