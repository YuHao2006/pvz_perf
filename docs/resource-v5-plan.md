# reanim_v5 / particle_v5 图集设计草案

状态：下一大版本的设计约束，尚未实现；与正在实施的 DAT64 纳秒时间迁移分开。

## 已确定的目标

- 发行时，一份 reanim 或 particle 定义对应自己的图集。
- compiled 定义直接描述图集中的矩形区域，不再用全局 ImageSymbolId 定位图片。
- 只被 reanim / particle 使用的图片，只进入包内对应图集，不再单独加入运行时
  编号纹理资源表或保存一份独立运行图片。
- 被 UI、字体、游戏代码等直接使用的图片仍有独立的资源归属；
  不能只依据动画文件引用就把它们删掉。
- 图集在构建阶段生成，运行时只加载、绑定图集及矩形元数据。
  不增加运行时打包、源码图片驻留或测试插桩。
- 公共元数据用 public 字段，通过 const& 传递只读记录，不新增访问器。

## 资源闭包与所有权

构建工具需要分别建立定义图片集合和直接使用集合：

| 分类 | 发行策略 |
| --- | --- |
| 仅被 reanim/particle 使用 | 写入定义图集；不发行独立 PNG/JPG/alpha 配图或编号纹理描述符 |
| 同时被定义和 UI/代码使用 | UI/代码所需资源保留；图集内的使用按定义规则处理，报告重复像素成本 |
| 字体字形页及其 alpha | 由真实 compiled font 引用保护，不按文件名或 IMAGE_ token 粗略删除 |
| 动态生成、可写渲染图片、滤镜派生图 | 保留自己的生命周期，不写回不可变定义图集 |

资源表的自动生成声明、分组加载绑定不能被误判成游戏代码的真实使用根。
反过来，真实代码引用、字体引用、动态覆写及区域别名也不能被漏掉。
专用图片不在运行时编号表注册；离线作者数据仍可使用原有名字解析来源。

## compiled 区域信息

矩形至少要区分：

- 图集中的实际像素区域。
- 原始逻辑宽高及裁剪/偏移信息，避免打包改变角色位置、粒子大小或鼠标区域。
- 粒子条带的 rows / cols / frame 语义，不能把整张图集尺寸当作单帧尺寸。
- 透明边界和滤波所需边缘扩展。

相同区域在一个定义内反复使用时，可在定义内去重；
局部区域引用不是全局 ImageSymbolId。是否采用局部区域表、字段位宽及
具体 wire 编号仍需与编译器和加载器一起确定，不仅修改文件后缀。
现有容器/元数据标记应明确分派，不能让旧 symbol 载荷误读为矩形。

文本/字体轨道、无图轨道、精确 fullscreen 轨道、动态图像覆写等行为保持独立，
不为图集化改写动画语义或绘制顺序。

## 打包与兼容边界

- RGB 与独立 alpha 在离线阶段按现行组合语义处理，验证颜色与透明度等价。
- 不旋转子图；先保证像素与矩形的直接映射。
- 透明图集子区需要边缘扩展和区域采样限制，防止线性过滤串色。
- 严格保留现行 mipmap、repeat、色彩空间和混合行为；不能一概改成整图
  CLAMP 或把某一个子图的边缘延伸到其他子图。
- 每个定义只对应一个图集时，超过目标后端最大纹理尺寸、无图片的定义以及
  跨定义共用图片的策略要明确，不能静默拆成多页或悄悄恢复独立编号图片。
- 稳定生成顺序和打包算法，记录源像素、派生图及 compiled 的校验信息。

当前 OpenGL / DX9 已有按定义分组的 atlas 数据与运行时区域管理，
v5 应审查如何替代它们，避免新的发行图集进入旧路径后再次打包。
绑定层采用图集的物理存储，逻辑宽高、UV、clip 等仍按子图处理。

## 性能验收

图集减少纹理切换有利于旧式绑定路径，但不能把这一点直接换算为 bindless
路径的收益百分比。Vulkan / DX12 已经使用描述符数组，需要单独测量；
按定义打包也可能增加跨定义重复图片的显存与包体。

验收使用独立测试和已有外部观测工具，不向正式游戏添加帧计数探针或日志：

- 对相同画面的像素、alpha、clip、混合和动画轨道结果做回归。
- 分别测 Vulkan、DX12、OpenGL、DX9 的 CPU 绘制与 GPU 帧时间。
- 记录纹理/图集数、驻留字节、包体、装载耗时、打包利用率和跨定义重复像素。
- 不能仅凭 draw call 变少认定更快，也不能仅凭 bindless 已有批处理认定图集无收益。
