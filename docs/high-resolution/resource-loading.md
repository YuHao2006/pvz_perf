# 高清分支：资源加载与显存说明

本文仅适用于高清开发分支 `high-resolution-v4.0.3`，不描述普通版 `main` 的资源策略，也不作为普通版发行要求。

## 当前没有按场景动态加载／卸载

**高清分支目前没有实现按场景动态加载、卸载高清纹理的机制。** 当前资源沿用现有装载和保留方式；进入商店、图鉴、成就或大头贴界面后，不保证自动卸载此前场景的纹理。不能把高清开发版理解为已完成低显存适配的版本。

现有的加载线程、首次使用时的纹理创建，以及关卡临时纹理的生命周期管理，不等于一套按场景管理全部高清图集的动态驻留系统。本文不承诺所有资源都在同一瞬间上传；说明的是目前没有完善的场景切换卸载和显存预算管理。

## 4×像素与显存的关系

4×表示图片的宽、高分别为原来的4倍，因此相同布局、相同RGBA8格式下，像素存储量为原来的16倍。例如260 MiB×16＝4160 MiB，约4.06 GiB；若原始数据采用十进制MB，则为4.16 GB。

单张RGBA8纹理的基础像素存储量通常按 `宽×高×4字节` 计算。若创建完整mipmap链，还需要额外空间。帧缓冲、深度缓冲、运行时合成纹理、上传缓冲、驱动分配与对齐等也应另计。因此，下列数字不能混用：

- PAK64／PNG的压缩文件体积。
- 解码后的全部图片像素总量。
- 实际同时驻留的GPU纹理总量。
- 游戏进程的显存峰值与主内存峰值。

2026-11-17转换独立不透明图片为JPEG之前的全量4×包检查中，416张PNG按RGBA8计算合计为3,269,662,160字节，约3.05 GiB。其中199张定义／界面图集合计为1,832,704,400字节，约1.71 GiB，其余独立贴图和字体页合计约1.34 GiB；固定256×256焦散计算输入另计。以上是包内图片全部解码后的基础像素合计，不包括运行时分配、额外mipmap或驱动开销，也不是实测同时驻留显存峰值。对应包SHA-256为 `a7fd56c4458b8c8afe826f59dfaf326d9e37e8286714661b314811338b7f074c`，后续包更新时以新构建证书和运行时测量为准。

构建优化中提到的约117 GiB，是旧报告代码对多个共享变体反复计算同一图像哈希所造成的累计像素扫描量，**不是需要分配的显存或内存**。该重复哈希已改为构建期间每张图只计算一次。

## 当前包的定位

- 开发阶段直接使用4×／2400p资源包，图集最大边8192，采用MaxRects快速装箱。
- 母图保留实际原生或已批准修复分辨率；4×是构建导出规格。
- v4.1 的2×原生发行包从4×图集整页缩半得到，不重新装箱，保持归一化UV不变。相同布局与格式下，基础图集像素存储量约为4×包的四分之一。
- 有损压缩主要减小下载和存储体积；若运行时仍解码为RGBA8，不能因此认定显存会同比下降。

动态加载／卸载、纹理驻留预算和低显存设备适配仍需单独实现与验证，不能作为当前高清版已有能力宣传。

## 不透明图片的 JPEG 构建导出

2026-11-17 用户要求将不必要的 PNG 改为 JPG。当前将17张完全不透明且编码后确实更小的独立图片导出为 JPEG（质量95、4:4:4色度采样），通过显式清单绑定；传送带转 JPEG 更大，继续保留 PNG。透明图、字体、效果数据和混合图集保留 PNG，固定焦散输入保持原字节。

`assets/high-resolution/current/` 是当前运行／构建输入，可能为 PNG 或 JPEG。无损母图和 `exports4x/` 保留，不用 JPEG 反向替代母图。此后默认开发 PAK 为 PNG＋JPEG 混合编码，不能继续称为全无损包；此前另行提供的无损测试包不受修改。

17张源文件合计由285,410,418降至40,542,889字节。压缩前后宽高、逻辑尺寸和UV不变，基础GPU纹理容量不因此降低。逐图来源、哈希和客观误差见 `assets/source-art/work/opaque-jpeg-20261117/conversion.json`。

2×派生对PNG整页缩半；JPEG独立图片从保留的无损4×PNG重新缩半并编码，避免从4×JPEG重复压缩。两者均不重新装箱，归一化UV不变。打包工具检查JPEG白名单与母图完整性，不允许把透明图误存成JPEG。

此次实际4×PAK为519,013,350字节（对照此前纯PNG参考包763,953,726字节）；2×资源包为123,729,310字节。启动检查及4×／2× Credits全画幅回归均通过。这里只完成资源包构建，未发布新的完整网页或桌面发行包。

## v4.1 原生发行

仅 Windows 10／Vulkan 1.3 与 Android 14／Armv9-A／Vulkan 1.3 两个原生包携带2×资源；4×母包继续用于开发。高清网页版本轮暂缓，没有构建或发布网页运行时。显存驻留限制保持不变。
