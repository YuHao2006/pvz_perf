# 原版 1073 正常动画速率上界

本次核对得到正常业务路径的 `abs(mAnimRate)` 保守上界为 **80**，来自钻石和火豌豆。
不包含调试加速、外部改值或把互斥模式状态强行组合。结论来自实际 1073 EXE 的钻石赋值、
146 份该安装提取的 reanim 作者数据，以及本项目 v1.0/v2.0 历史业务路径复核；
不是对 EXE 每条指令的形式化穷尽证明。

参考 EXE：`C:/UserProgram/Plants_Vs_Zombies_V1.2.0.1073_EN/PlantsVsZombies.exe`，
SHA256 `5F650F52D12751E08B63E590EDB0D9B9F09D087CEA900BAA0EB39E4AF8EDA251`。

Credits_Football 的同步公式为 `194/30*30/(64/12)=36.375`，

## 与单步跨关键帧的关系

`mAnimRate` 不是所有播放模式下的实际源关键帧频率。动作 N 帧时，
普通模式的有效区间为 N−1，full-last 模式为 N：

```text
sourceFramesPerSecond = abs(mAnimRate) * intervalCount / frameCount
```

钻石 N=52，普通循环的有效源关键帧速率上界为 `80*51/52≈78.461538/s`；
火豌豆 N=25，上界为 76.8/s。迷你橄榄球为 `63.92*29/30≈61.789333/s`。
因此 80Hz／12.5ms 是简单、留有余量的动画单步上限；不能只根据设置中的绘制 FPS
断言更新间隔不会超限。掉帧、调度延迟和补拍都必须按实际逻辑步长处理。

现行产品策略进一步将目标 FPS 最低设为 100，不保留低频目标调度路径。
单步仍最多 10ms，高频目标逾期也受同一上限约束；超出 10ms 的目标步长会被拒绝。
原版 100Hz 正常逻辑足以覆盖本次查到的最大速率。
