## 粒子缓存的实际边界

两进程、每组五轮取min。缓存／未缓存的完整渲染参数输出逐粒子相同。query_only把更新放在计时外；refresh_and_query将一次发射器刷新及512粒子的逐项刷新计入，再分别消费1/2/4次。后者是刷新加渲染查询的受控范围，不包含完整物理更新；实际物理更新本来也会计算当前年龄，因此不把这些数字直接等同于整局成本。

| 用例 | 未缓存ns/查询，进程1／2 | 侧表ns/查询，进程1／2 |
| --- | ---: | ---: |
| 默认快路，仅查询一次 | 83.618／83.829 | 83.614／83.831 |
| 有轨道，仅查询一次 | 203.883／204.190 | 198.534／198.808 |
| 默认快路，刷新＋一次查询 | 83.601／83.784 | 93.130／93.253 |
| 有轨道，刷新＋一次查询 | 204.283／204.564 | 208.767／208.895 |
| 有轨道，刷新＋两次查询 | 204.317／204.153 | 203.711／203.638 |
| 有轨道，刷新＋四次查询 | 204.324／204.284 | 201.562／201.205 |

缓存不是每种场景都更快：默认快路没有查询收益，单次查询不足以覆盖额外刷新；多次消费同一比例时才逐步摊薄成本。完整各轮和汇总见particle-summary.json。不推导手机功耗或整机FPS收益。
